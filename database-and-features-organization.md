# Pomar na Mão — Arquitetura Database

Este documento consolida o modelo de dados necessário para o painel de mapa e para os processos de campo do aplicativo **Pomar na Mão**, considerando:

- PostgreSQL/Supabase como banco remoto.
- React Native com SQLite como banco local/offline.
- Operações feitas em campo e sincronizadas posteriormente.
- Plantas com latitude/longitude.
- Histórico de ocorrências, inspeções, anotações e pulverizações.
- Consultas e RPCs nas operações envolvendo processamento multi tabelas ou com Postgis

> Observação importante: este documento não é um único script para execução completa. Os blocos SQL foram separados para facilitar a execução tabela por tabela no SQL Editor do Supabase.

---

## 1. Visão geral do modelo

O sistema precisa atender três grandes necessidades:

1. **Mapa**
   - Plotar todas as plantas.
   - Plotar polígonos das zonas/regiões.
   - Pintar plantas por ocorrência atual.
   - Pintar plantas por variedade.
   - Plotar rotas de pulverização.
   - Destacar plantas com anotações.
   - Destacar plantas por inspeção.

2. **Histórico**
   - Histórico de pulverizações por planta.
   - Histórico de ocorrências por planta.
   - Histórico de inspeções.
   - Histórico de anotações manuais.
   - Histórico geral da planta.

3. **Offline-first**
   - O app React Native coleta dados em campo.
   - Os dados são salvos primeiro no SQLite.
   - Quando houver internet, os dados são enviados para o Supabase.
   - O Supabase consolida os dados nas tabelas principais.

## 2. Extensão necessária

No Supabase, instale o PostGIS preferencialmente no schema `extensions` e use as funções/tipos qualificados com `extensions.`.

Execute este bloco antes de criar tabelas ou RPCs que usam `geography`, `st_distance`, `st_dwithin`, `st_makepoint`, `st_asgeojson`, etc.

```sql
create schema if not exists extensions;
create extension if not exists postgis with schema extensions;
```

> Se você recebeu o erro `type "geography" does not exist`, é porque o PostGIS não foi instalado ou o tipo `geography` não está no `search_path` usado pela query/RPC. Por isso os blocos abaixo usam `extensions.geography` e `extensions.st_*`. Sim, o banco exige sobrenome até para tipo geográfico, que delicadeza.

O PostGIS é necessário para:

- Buscar planta mais próxima de um ponto.
- Plotar pontos, linhas e polígonos.
- Calcular distâncias.
- Filtrar plantas por zona.
- Trabalhar com rotas de pulverização e inspeção.

## 3. Tabela `varieties`

Esta tabela já existe no banco.

```sql
create table public.varieties (
  id bigint generated by default as identity not null,
  name text not null,
  description text null,
  created_at timestamp with time zone not null default now(),
  constraint varieties_pkey primary key (id)
);
```

A tabela `plants` deve referenciar `varieties(id)`.

## 4. Tabela `zones`

Representa as zonas/regiões do pomar.

É usada para:

- Plotar polígonos no mapa.
- Filtrar plantas por zona.
- Criar inspeções por zona.
- Agrupar dados de produtividade, pulverização e ocorrência.

```sql
create table public.zones (
  id uuid primary key default gen_random_uuid(),

  name text not null,
  code text,
  description text,

  boundary extensions.geography(polygon, 4326),

  local_id text,
  device_id text,
  sync_status text not null default 'synced',
  synced_at timestamptz,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint uq_zones_name unique (name)
);

create index idx_zones_boundary
  on public.zones
  using gist (boundary);

create index idx_zones_code
  on public.zones (code);
```

## 5. Tabela `plants`

Representa o cadastro/base de cada planta.

A planta tem localização fixa e referência para variedade e zona.

```sql
create table public.plants (
  id uuid primary key default gen_random_uuid(),

  latitude double precision not null,
  longitude double precision not null,

  location extensions.geography(point, 4326)
    generated always as (
      extensions.st_setsrid(extensions.st_makepoint(longitude, latitude), 4326)::extensions.geography
    ) stored,

  gps_timestamp bigint,

  variety_id bigint references public.varieties(id) on delete set null,
  zone_id uuid references public.zones(id) on delete set null,

  mass text,
  harvest text,
  description text,
  planting_date timestamptz,
  life_of_the_tree text,

  is_dead boolean not null default false,
  is_new boolean not null default false,
  non_existent boolean not null default false,

  local_id text,
  device_id text,
  sync_status text not null default 'synced',
  synced_at timestamptz,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index idx_plants_location
  on public.plants
  using gist (location);

create index idx_plants_zone_id
  on public.plants (zone_id);

create index idx_plants_variety_id
  on public.plants (variety_id);

create index idx_plants_sync_status
  on public.plants (sync_status);
```

## 8. Tabela `field_operations`

Representa qualquer operação feita em campo.

Exemplos:

- Pulverização.
- Adubação.
- Colheita.
- Inspeção.
- Anotação de ocorrência.

```sql
create table public.field_operations (
  id uuid primary key default gen_random_uuid(),

  operation_type_id uuid not null references public.operation_types(id),
  zone_id uuid references public.zones(id) on delete set null,
  target_occurrence_type_id uuid references public.occurrence_types(id) on delete set null,

  title text,
  source text not null default 'manual',
  -- manual, gps_track, imported, automatic

  started_at timestamptz not null,
  finished_at timestamptz,

  operator_name text,
  machine_name text,
  tractor_identifier text,

  notes text,
  map_color text,

  local_id text,
  device_id text,
  sync_status text not null default 'pending',
  synced_at timestamptz,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint chk_field_operations_source
    check (source in ('manual', 'gps_track', 'imported', 'automatic'))
);

create index idx_field_operations_type
  on public.field_operations (operation_type_id);

create index idx_field_operations_zone
  on public.field_operations (zone_id);

create index idx_field_operations_started_at
  on public.field_operations (started_at);

create index idx_field_operations_sync_status
  on public.field_operations (sync_status);
```

## 9. Tabela `field_operation_track_points`

Guarda os pontos GPS de uma operação com rota.

Usada principalmente em:

- Pulverização.
- Adubação.
- Colheita.
- Qualquer operação feita por máquina ou veículo com rastreamento.

```sql
create table public.field_operation_track_points (
  id bigserial primary key,

  field_operation_id uuid not null
    references public.field_operations(id)
    on delete cascade,

  recorded_at timestamptz not null,

  latitude double precision not null,
  longitude double precision not null,

  location extensions.geography(point, 4326)
    generated always as (
      extensions.st_setsrid(extensions.st_makepoint(longitude, latitude), 4326)::extensions.geography
    ) stored,

  speed_mps numeric(10, 3),
  accuracy_m numeric(10, 3),

  local_id text,
  device_id text,
  sync_status text not null default 'pending',
  synced_at timestamptz,

  created_at timestamptz not null default now()
);

create index idx_track_points_operation
  on public.field_operation_track_points (field_operation_id);

create index idx_track_points_location
  on public.field_operation_track_points
  using gist (location);

create index idx_track_points_recorded_at
  on public.field_operation_track_points (recorded_at);
```

## 11. Tabela `plant_operation_history`

Associa plantas a operações.

É uma das tabelas mais importantes para histórico.

Serve para responder:

- Quais plantas foram pulverizadas?
- Quais operações afetaram uma planta?
- Quais plantas foram atingidas por determinada operação?
- Qual foi a distância da planta até a rota?

```sql
create table public.plant_operation_history (
  id uuid primary key default gen_random_uuid(),

  plant_id uuid not null
    references public.plants(id)
    on delete cascade,

  field_operation_id uuid not null
    references public.field_operations(id)
    on delete cascade,

  operation_type_id uuid not null
    references public.operation_types(id),

  matched_at timestamptz,
  nearest_track_point_id bigint
    references public.field_operation_track_points(id)
    on delete set null,

  distance_meters numeric(10, 3),

  match_source text not null default 'auto_matched',
  -- auto_matched, manual_added, imported

  status text not null default 'confirmed',
  -- confirmed, pending, ignored

  notes text,

  local_id text,
  device_id text,
  sync_status text not null default 'pending',
  synced_at timestamptz,

  created_at timestamptz not null default now(),

  constraint uq_plant_operation unique (plant_id, field_operation_id)
);

create index idx_plant_operation_history_plant
  on public.plant_operation_history (plant_id);

create index idx_plant_operation_history_operation
  on public.plant_operation_history (field_operation_id);

create index idx_plant_operation_history_type
  on public.plant_operation_history (operation_type_id);

create index idx_plant_operation_history_created_at
  on public.plant_operation_history (created_at);
```

## 13. Tabela `plant_occurrences`

Guarda ocorrências observadas em plantas.

É a principal tabela para histórico de ocorrência.

```sql
create table public.plant_occurrences (
  id uuid primary key default gen_random_uuid(),

  plant_id uuid not null
    references public.plants(id)
    on delete cascade,

  occurrence_type_id uuid not null
    references public.occurrence_types(id),

  field_operation_id uuid
    references public.field_operations(id)
    on delete set null,

  plant_operation_history_id uuid
    references public.plant_operation_history(id)
    on delete set null,

  observed_at timestamptz not null default now(),

  severity text,
  status text not null default 'open',
  -- open, resolved, ignored

  notes text,

  annotation_latitude double precision,
  annotation_longitude double precision,

  annotation_location extensions.geography(point, 4326)
    generated always as (
      case
        when annotation_longitude is not null and annotation_latitude is not null
        then extensions.st_setsrid(extensions.st_makepoint(annotation_longitude, annotation_latitude), 4326)::extensions.geography
        else null
      end
    ) stored,

  gps_accuracy_m numeric(10, 3),
  assigned_distance_meters numeric(10, 3),

  assignment_method text not null default 'manual',
  -- manual, nearest_plant, corrected_by_user

  assignment_status text not null default 'confirmed',
  -- pending_review, confirmed, rejected

  resolved_at timestamptz,

  local_id text,
  device_id text,
  sync_status text not null default 'pending',
  synced_at timestamptz,

  created_at timestamptz not null default now(),

  constraint chk_plant_occurrences_assignment_method
    check (assignment_method in ('manual', 'nearest_plant', 'corrected_by_user')),

  constraint chk_plant_occurrences_assignment_status
    check (assignment_status in ('pending_review', 'confirmed', 'rejected'))
);

create index idx_plant_occurrences_plant
  on public.plant_occurrences (plant_id);

create index idx_plant_occurrences_type
  on public.plant_occurrences (occurrence_type_id);

create index idx_plant_occurrences_observed_at
  on public.plant_occurrences (observed_at);

create index idx_plant_occurrences_status
  on public.plant_occurrences (status);

create index idx_plant_occurrences_annotation_location
  on public.plant_occurrences
  using gist (annotation_location);
```

# 17. Consultas para plots do mapa

## 17.1. Plot inicial: todas as plantas

```sql
select
  p.id,
  p.latitude,
  p.longitude,
  p.zone_id,
  z.name as zone_name,
  p.variety_id,
  v.name as variety_name,
  p.is_dead,
  p.is_new,
  p.non_existent
from public.plants p
left join public.zones z on z.id = p.zone_id
left join public.varieties v on v.id = p.variety_id
where p.non_existent = false;
```

---

## 17.2. Botão: polígonos das zonas/regiões

```sql
select
  id,
  name,
  code,
  description,
  extensions.st_asgeojson(boundary)::json as boundary_geojson
from public.zones
where boundary is not null;
```

---

## 17.3. Botão: plantas com ocorrências atuais

```sql
select
  p.id as plant_id,
  p.latitude,
  p.longitude,
  po.id as occurrence_id,
  po.observed_at,
  po.severity,
  po.status,
  ot.code as occurrence_code,
  ot.name as occurrence_name
from public.plant_occurrences po
join public.plants p on p.id = po.plant_id
join public.occurrence_types ot on ot.id = po.occurrence_type_id
where po.status = 'open'
order by ot.name, po.observed_at desc;
```

---

## 17.4. Botão: plantas pintadas por variedade

```sql
select
  p.id,
  p.latitude,
  p.longitude,
  p.variety_id,
  v.name as variety_name
from public.plants p
left join public.varieties v on v.id = p.variety_id
where p.non_existent = false;
```

---

## 17.5. Botão: rotas de pulverização por período

```sql
select
  fo.id as field_operation_id,
  fo.title,
  fo.started_at,
  fo.finished_at,
  fo.machine_name,
  fo.operator_name,
  fo.tractor_identifier,
  foroute.distance_meters,
  extensions.st_asgeojson(foroute.route)::json as route_geojson
from public.field_operations fo
join public.operation_types ot
  on ot.id = fo.operation_type_id
join public.field_operation_routes foroute
  on foroute.field_operation_id = fo.id
where ot.code = 'spraying'
  and fo.started_at >= :start_date
  and fo.started_at <= :end_date
order by fo.started_at desc;
```

---

## 17.6. Botão: plantas com anotações por período

```sql
select
  po.id as annotation_id,
  p.id as plant_id,
```

# 18. RPCs úteis para o frontend

## 18.1. Buscar planta mais próxima

Esta versão evita o erro `type "geography" does not exist` usando `extensions.geography` e funções PostGIS qualificadas. Execute antes a extensão da seção 2.

```sql
create or replace function public.find_nearest_plant(
  p_latitude double precision,
  p_longitude double precision,
  p_zone_id uuid default null,
  p_max_distance_meters double precision default 10
)
returns table (
  plant_id uuid,
  distance_meters double precision
)
language sql
security definer
set search_path = public
as $$
  with point as (
    select extensions.st_setsrid(extensions.st_makepoint(p_longitude, p_latitude), 4326)::extensions.geography as location
  )
  select
    p.id as plant_id,
    extensions.st_distance(p.location, point.location) as distance_meters
  from public.plants p, point
  where (p_zone_id is null or p.zone_id = p_zone_id)
    and extensions.st_dwithin(
      p.location,
      point.location,
      p_max_distance_meters
    )
  order by extensions.st_distance(p.location, point.location)
  limit 1;
$$;
```

# 20. Fluxos offline-first por processo

Esta seção descreve como o aplicativo deve disponibilizar dados e coletar dados em campo para cada processo.

A ideia é:

1. Baixar dados necessários do Supabase.
2. Salvar no SQLite.
3. Operar offline no campo.
4. Marcar registros locais como pendentes.
5. Sincronizar com Supabase depois.
6. Atualizar o SQLite com os IDs remotos e status de sincronização.

## 20.2. Processo: inspeção

### 20.2.1. Objetivo da funcionalidade

A funcionalidade de inspeção permite que o usuário vá a campo, filtre plantas por **zona** e/ou **ocorrência**, visualize essas plantas no mapa, identifique automaticamente a planta mais próxima conforme anda pelo pomar e edite as ocorrências ou informações relevantes dessa planta.

A inspeção deve salvar localmente apenas as plantas que sofreram alteração. Depois, a lista de inspeções fica disponível no aplicativo com uma ação de **Swipeable** para sincronizar os dados com o Supabase.

---

## 20.2.2. Comportamento inicial da tela

### Ao entrar na funcionalidade de inspeção

O aplicativo deve carregar:

1. Mapa vazio.
2. Localização atual do usuário.
3. Botão para abrir modal de filtro.
4. Botão para abrir modal de detalhes/edição da planta mais próxima.
5. Lista local de inspeções pendentes ou já realizadas.

Neste primeiro momento, nenhuma planta precisa ser carregada automaticamente. O objetivo é evitar carregar dados desnecessários antes de o usuário definir a zona ou ocorrência. Um raro momento de lucidez para economizar bateria, internet e sofrimento.

---

## 20.2.3. Modal de filtro da inspeção

### Campos do modal

O modal deve conter dois campos principais:

```txt
zona
ocorrencia
```

Ambos podem ser opcionais, dependendo da regra do aplicativo.

### Possíveis combinações

#### 1. Filtrar apenas por zona

Busca todas as plantas daquela zona.

```txt
zona = Zona A
ocorrencia = null
```

#### 2. Filtrar apenas por ocorrência

Busca todas as plantas que possuem determinada ocorrência aberta, independentemente da zona.

```txt
zona = null
ocorrencia = Formigueiro
```

#### 3. Filtrar por zona e ocorrência

Busca plantas daquela zona que possuem aquela ocorrência aberta.

```txt
zona = Zona A
ocorrencia = Formigueiro
```

#### 4. Sem filtro

Pode ser bloqueado ou permitido conforme a estratégia do app.

Recomendação: bloquear em pomares grandes para evitar carregar plantas demais no celular.

## 20.2.9. Detecção da planta mais próxima

## 20.2.17. RPC recomendada para sincronizar inspeção

Criar uma RPC no Supabase para receber o payload inteiro.

### RPC: `sync_manual_inspection`

```sql
create or replace function public.sync_manual_inspection(
  p_payload jsonb
)
returns table (
  field_operation_id uuid,
  created_occurrences_count integer,
  updated_occurrences_count integer,
  resolved_occurrences_count integer
)
language plpgsql
security definer
set search_path = public
as $$
declare
  v_operation_type_id uuid;
  v_field_operation_id uuid;
  v_zone_id uuid;
  v_occurrence_type_id uuid;
  v_started_at timestamptz;
  v_finished_at timestamptz;
  v_device_id text;

  v_plant jsonb;
  v_change jsonb;

  v_created_count integer := 0;
  v_updated_count integer := 0;
  v_resolved_count integer := 0;

  v_existing_occurrence_id uuid;
begin
  v_zone_id := nullif(p_payload->>'zoneId', '')::uuid;
  v_occurrence_type_id := nullif(p_payload->>'occurrenceTypeId', '')::uuid;
  v_started_at := nullif(p_payload->>'startedAt', '')::timestamptz;
  v_finished_at := nullif(p_payload->>'finishedAt', '')::timestamptz;
  v_device_id := p_payload->>'deviceId';

  select id
  into v_operation_type_id
  from public.operation_types
  where code = 'manual_inspection';

  if v_operation_type_id is null then
    raise exception 'operation_types.code manual_inspection não encontrado';
  end if;

  insert into public.field_operations (
    operation_type_id,
    zone_id,
    target_occurrence_type_id,
    source,
    title,
    started_at,
    finished_at,
    device_id,
    local_id,
    sync_status,
    synced_at
  )
  values (
    v_operation_type_id,
    v_zone_id,
    v_occurrence_type_id,
    'manual',
    'Inspeção manual',
    coalesce(v_started_at, now()),
    v_finished_at,
    v_device_id,
    p_payload->>'localInspectionId',
    'synced',
    now()
  )
  returning id into v_field_operation_id;

  for v_plant in
    select * from jsonb_array_elements(coalesce(p_payload->'plantsChanged', '[]'::jsonb))
  loop
    insert into public.plant_operation_history (
      plant_id,
      field_operation_id,
      operation_type_id,
      match_source,
      status,
      notes
    )
    values (
      (v_plant->>'plantId')::uuid,
      v_field_operation_id,
      v_operation_type_id,
      'manual_added',
      'confirmed',
      'Planta alterada durante inspeção manual'
    )
    on conflict (plant_id, field_operation_id) do nothing;

    for v_change in
      select * from jsonb_array_elements(coalesce(v_plant->'changes', '[]'::jsonb))
    loop
      v_existing_occurrence_id := null;

      select po.id
      into v_existing_occurrence_id
      from public.plant_occurrences po
      where po.plant_id = (v_plant->>'plantId')::uuid
        and po.occurrence_type_id = (v_change->>'occurrenceTypeId')::uuid
        and po.status = 'open'
      order by po.observed_at desc
      limit 1;

      if v_change->>'changeType' = 'add_occurrence' then
        if v_existing_occurrence_id is null then
          insert into public.plant_occurrences (
            plant_id,
            occurrence_type_id,
            field_operation_id,
            observed_at,
            severity,
            status,
            notes,
            annotation_latitude,
            annotation_longitude,
            gps_accuracy_m,
            assigned_distance_meters,
            assignment_method,
            assignment_status,
            local_id,
            device_id,
            sync_status,
            synced_at
          )
          values (
            (v_plant->>'plantId')::uuid,
            (v_change->>'occurrenceTypeId')::uuid,
            v_field_operation_id,
            coalesce(nullif(v_change->>'changedAt', '')::timestamptz, now()),
            nullif(v_change->>'severity', ''),
            'open',
            nullif(v_change->>'notes', ''),
            nullif(v_change->>'latitude', '')::double precision,
            nullif(v_change->>'longitude', '')::double precision,
            nullif(v_change->>'gpsAccuracyM', '')::numeric,
            nullif(v_change->>'distanceToPlantMeters', '')::numeric,
            'manual',
            'confirmed',
            v_change->>'localChangeId',
            v_device_id,
            'synced',
            now()
          );

          v_created_count := v_created_count + 1;
        end if;

      elsif v_change->>'changeType' = 'update_occurrence' then
        if v_existing_occurrence_id is not null then
          update public.plant_occurrences
          set
            severity = coalesce(nullif(v_change->>'severity', ''), severity),
            notes = coalesce(nullif(v_change->>'notes', ''), notes),
            field_operation_id = v_field_operation_id,
            updated_at = now(),
            sync_status = 'synced',
            synced_at = now()
          where id = v_existing_occurrence_id;

          v_updated_count := v_updated_count + 1;
        end if;

      elsif v_change->>'changeType' in ('remove_occurrence', 'resolve_occurrence') then
        if v_existing_occurrence_id is not null then
          update public.plant_occurrences
          set
            status = 'resolved',
            resolved_at = coalesce(nullif(v_change->>'changedAt', '')::timestamptz, now()),
            field_operation_id = v_field_operation_id,
            notes = coalesce(nullif(v_change->>'notes', ''), notes),
            updated_at = now(),
            sync_status = 'synced',
            synced_at = now()
          where id = v_existing_occurrence_id;

          v_resolved_count := v_resolved_count + 1;
        end if;
      end if;
    end loop;
  end loop;

  return query
  select
    v_field_operation_id,
    v_created_count,
    v_updated_count,
    v_resolved_count;
end;
$$;
```

## 20.2.19. Regras importantes

### Só sincronizar plantas alteradas

Não envie todas as plantas carregadas no mapa.

Envie apenas plantas com registros em:

```txt
local_inspection_changes
```

Isso reduz tráfego, evita duplicação e impede que uma inspeção vire uma carreta de JSON sem necessidade.

### Não criar ocorrência duplicada

Antes de criar uma ocorrência aberta, a RPC deve verificar se já existe uma ocorrência aberta para:

```txt
plant_id
occurrence_type_id
status = open
```

Se já existir, pode:

1. Ignorar.
2. Atualizar severidade/notas.
3. Registrar nova observação histórica.

A recomendação para MVP é:

```txt
se já existe aberta, atualizar
se não existe, criar
```

### Remover ocorrência não significa deletar

Quando o usuário remover uma ocorrência no app, não delete o registro no Supabase.

Atualize:

```txt
status = resolved
resolved_at = now()
```

Histórico não é lixo. Apagar histórico é como fingir que bug nunca existiu: popular, inútil e moralmente questionável.

### Salvar localização da edição

Sempre que possível, salve:

```txt
latitude
longitude
gps_accuracy_m
distance_to_plant_meters
```

Isso ajuda a auditar se o usuário estava perto da planta quando alterou a ocorrência.

### Manter dados offline até confirmar sincronização

Só marque como sincronizado no SQLite depois que a RPC retornar sucesso.

Atualizar localmente:

```txt
local_inspections.sync_status = synced
local_inspections.remote_field_operation_id = field_operation_id retornado
local_inspections.synced_at = now

local_inspection_changes.sync_status = synced
```

Se falhar:

```txt
local_inspections.sync_status = error
local_inspections.sync_error = mensagem do erro

local_inspection_changes.sync_status = pending ou error
```

## 20.2.20. Resumo do fluxo completo

### 1. Usuário entra em inspeção

1.1. App abre mapa vazio.  
1.2. App mostra localização atual.  
1.3. App mostra botão de filtro.  
1.4. App mostra botão de detalhes da planta mais próxima.

### 2. Usuário abre modal de filtro

2.1. App lista zonas.  
2.2. App lista ocorrências.  
2.3. Usuário seleciona zona e/ou ocorrência.  
2.4. Usuário confirma filtro.

### 3. App busca dados no Supabase

3.1. App chama `get_inspection_plants`.  
3.2. App recebe plantas filtradas.  
3.3. App agrupa ocorrências por planta.  
3.4. App cria uma inspeção local.  
3.5. App salva plantas filtradas no SQLite.

### 4. App plota plantas no mapa

4.1. App lê `local_inspection_loaded_plants`.  
4.2. App plota os marcadores no mapa.  
4.3. App diferencia visualmente plantas comuns, alteradas e planta mais próxima.

### 5. Usuário anda pelo pomar

5.1. App recebe atualizações de GPS.  
5.2. App calcula a planta mais próxima.  
5.3. App salva a planta mais próxima.  
5.4. App muda a cor da planta no mapa.

### 6. Usuário abre modal da planta

6.1. App carrega a última planta mais próxima.  
6.2. App mostra variedade, zona, ocorrências e distância.  
6.3. Usuário adiciona, remove ou edita ocorrências.

### 7. App salva alterações

7.1. App salva alterações em `local_inspection_changes`.  
7.2. App atualiza o array de plantas alteradas.  
7.3. App atualiza o marcador da planta no mapa.  
7.4. App atualiza contador de plantas alteradas na inspeção local.

### 8. Usuário finaliza inspeção

8.1. App marca inspeção como `finished`.  
8.2. App mantém `sync_status = pending`.  
8.3. App exibe inspeção na lista local.

### 9. Usuário sincroniza pelo Swipeable

9.1. App monta `SyncInspectionPayload`.  
9.2. App chama `sync_manual_inspection`.  
9.3. Supabase cria `field_operations`.  
9.4. Supabase cria registros em `plant_operation_history`.  
9.5. Supabase cria, atualiza ou resolve registros em `plant_occurrences`.  
9.6. App marca inspeção como sincronizada no SQLite.

## 20.3. Processo: anotação de ocorrência

A anotação acontece quando o usuário marca uma ocorrência no campo e o app atribui a ocorrência à planta mais próxima.

### 20.3.1. Dados que o app precisa disponibilizar

Antes da anotação, o app precisa ter no SQLite:

```txt
plants com latitude/longitude
occurrence_types
zones, opcional
operation_types
```

### 20.3.2. Fluxo no aplicativo

1. Usuário abre o módulo de anotação.
2. Usuário seleciona o tipo de ocorrência.
3. App captura a localização atual do aparelho.
4. App busca no SQLite a planta mais próxima.
5. App calcula a distância entre o ponto capturado e a planta.
6. Se a distância estiver dentro do limite permitido, app sugere a planta.
7. Usuário confirma ou corrige a planta.
8. App cria uma operação local do tipo `occurrence_annotation`.
9. App cria uma ocorrência local em `plant_occurrences`.
10. App salva latitude/longitude original da anotação.
11. App salva a distância até a planta atribuída.
12. Quando houver internet, app sincroniza com Supabase.

## 20.4. Processo: pulverização

A pulverização acontece com rota GPS e pode associar automaticamente plantas próximas ao trajeto.


```txt

```

### 20.4.2. Fluxo no aplicativo

1. Usuário abre o módulo de pulverização.
2. Usuário seleciona zona, se aplicável.
3. Usuário informa operador, máquina/trator e produtos aplicados.
4. App cria uma operação local do tipo `spraying`.
5. App começa a capturar pontos GPS.
6. App salva cada ponto no SQLite.
7. App pode mostrar a rota em tempo real.
8. Ao finalizar, app fecha a operação.

11. App cria registros locais em `plant_operation_history`.
12. Quando houver internet, app sincroniza operação, pontos, rota, insumos e plantas atingidas.

### 20.4.5. Associação de plantas à rota

Existem duas estratégias.

#### Estratégia A: associar no app

O app calcula localmente quais plantas estão próximas da rota.

Vantagens:

```txt
- usuário consegue ver resultado offline
- app já mostra plantas atingidas
- sincronização envia resultado pronto
```

Desvantagens:

```txt
- cálculo pode ser mais pesado no celular
- precisa implementar distância entre ponto/planta ou linha/planta
```

#### Estratégia B: associar no Supabase

O app envia operação e pontos GPS.

O Supabase calcula as plantas próximas usando PostGIS.

Vantagens:

```txt
- cálculo mais confiável
- lógica centralizada no banco
- usa índice espacial
```

Desvantagens:

```txt
- resultado só aparece depois da sincronização
- sem internet, usuário não vê associação consolidada
```

Sugestão prática:

```txt
- No app: fazer associação preliminar.
- No Supabase: recalcular/confirmar associação oficial.
```

### 20.4.7. SQL para associar plantas próximas à rota pelos pontos

Exemplo usando distância máxima de 3 metros:

```sql
insert into public.plant_operation_history (
  plant_id,
  field_operation_id,
  operation_type_id,
  nearest_track_point_id,
  matched_at,
  distance_meters,
  match_source,
  status,
  sync_status,
  synced_at
)
select distinct on (p.id)
  p.id as plant_id,
  fo.id as field_operation_id,
  fo.operation_type_id,
  tp.id as nearest_track_point_id,
  tp.recorded_at as matched_at,
  extensions.st_distance(p.location, tp.location) as distance_meters,
  'auto_matched' as match_source,
  'confirmed' as status,
  'synced' as sync_status,
  now() as synced_at
from public.field_operations fo
join public.field_operation_track_points tp
  on tp.field_operation_id = fo.id
join public.plants p
  on extensions.st_dwithin(p.location, tp.location, 3)
where fo.id = :field_operation_id
order by p.id, extensions.st_distance(p.location, tp.location)
on conflict (plant_id, field_operation_id) do update set
  nearest_track_point_id = excluded.nearest_track_point_id,
  matched_at = excluded.matched_at,
  distance_meters = excluded.distance_meters,
  match_source = excluded.match_source,
  status = excluded.status,
  sync_status = 'synced',
  synced_at = now();
```

### 20.4.8. RPC sugerida para recalcular plantas atingidas

```sql
create or replace function public.recalculate_operation_affected_plants(
  p_field_operation_id uuid,
  p_max_distance_meters double precision default 3
)
returns integer
language plpgsql
security definer
set search_path = public
as $$
declare
  v_count integer;
begin
  insert into public.plant_operation_history (
    plant_id,
    field_operation_id,
    operation_type_id,
    nearest_track_point_id,
    matched_at,
    distance_meters,
    match_source,
    status,
    sync_status,
    synced_at
  )
  select distinct on (p.id)
    p.id,
    fo.id,
    fo.operation_type_id,
    tp.id,
    tp.recorded_at,
    extensions.st_distance(p.location, tp.location),
    'auto_matched',
    'confirmed',
    'synced',
    now()
  from public.field_operations fo
  join public.field_operation_track_points tp
    on tp.field_operation_id = fo.id
  join public.plants p
    on extensions.st_dwithin(p.location, tp.location, p_max_distance_meters)
  where fo.id = p_field_operation_id
  order by p.id, extensions.st_distance(p.location, tp.location)
  on conflict (plant_id, field_operation_id) do update set
    nearest_track_point_id = excluded.nearest_track_point_id,
    matched_at = excluded.matched_at,
    distance_meters = excluded.distance_meters,
    match_source = excluded.match_source,
    status = excluded.status,
    sync_status = 'synced',
    synced_at = now();

  get diagnostics v_count = row_count;

  return v_count;
end;
$$;
```

# 23. Observação final

O app deve tratar o SQLite como fonte de verdade temporária durante o trabalho em campo.

O Supabase deve ser a fonte de verdade consolidada depois da sincronização.

Para evitar bagunça, todo registro criado offline deve ter:

```txt
local_id
device_id
sync_status
synced_at
```

E toda sincronização deve manter um mapa entre:

```txt
local_id -> id remoto
```

Sem isso, o app vai sincronizar duplicado, perder relacionamento entre tabelas e transformar o histórico agrícola em uma novela mexicana com GPS.

```sql
-- =========================================================
-- RPC: find_nearest_plant
-- =========================================================
create or replace function public.find_nearest_plant(
  p_latitude double precision,
  p_longitude double precision,
  p_zone_id uuid default null,
  p_max_distance_meters double precision default 10
)
returns table (
  plant_id uuid,
  distance_meters double precision
)
language sql
security definer
set search_path = public, extensions
as $$
  with point as (
    select extensions.st_setsrid(extensions.st_makepoint(p_longitude, p_latitude), 4326)::extensions.geography as location
  )
  select
    p.id as plant_id,
    extensions.st_distance(p.location, point.location) as distance_meters
  from public.plants p, point
  where (p_zone_id is null or p.zone_id = p_zone_id)
    and extensions.st_dwithin(p.location, point.location, p_max_distance_meters)
  order by p.location <-> point.location
  limit 1;
$$;

-- =========================================================
-- RPC: create_occurrence_annotation
-- =========================================================
create or replace function public.create_occurrence_annotation(
  p_occurrence_type_id uuid,
  p_latitude double precision,
  p_longitude double precision,
  p_zone_id uuid default null,
  p_notes text default null,
  p_severity text default null,
  p_gps_accuracy_m numeric default null,
  p_max_distance_meters double precision default 10,
  p_device_id text default null,
  p_local_id text default null
)
returns uuid
language plpgsql
security definer
set search_path = public, extensions
as $$
declare
  v_plant_id uuid;
  v_distance_meters double precision;
  v_operation_type_id uuid;
  v_field_operation_id uuid;
  v_occurrence_id uuid;
begin
  select plant_id, distance_meters
  into v_plant_id, v_distance_meters
  from public.find_nearest_plant(p_latitude, p_longitude, p_zone_id, p_max_distance_meters);

  if v_plant_id is null then
    raise exception 'Nenhuma planta encontrada próxima ao ponto informado';
  end if;

  select id into v_operation_type_id
  from public.operation_types
  where code = 'occurrence_annotation';

  insert into public.field_operations (
    operation_type_id, zone_id, source, title, started_at, finished_at,
    notes, local_id, device_id, sync_status, synced_at
  )
  values (
    v_operation_type_id, p_zone_id, 'manual', 'Anotação de ocorrência', now(), now(),
    p_notes, p_local_id, p_device_id, 'synced', now()
  )
  returning id into v_field_operation_id;

  insert into public.plant_occurrences (
    plant_id, occurrence_type_id, field_operation_id, observed_at, severity,
    status, notes, annotation_latitude, annotation_longitude, gps_accuracy_m,
    assigned_distance_meters, assignment_method, assignment_status,
    local_id, device_id, sync_status, synced_at
  )
  values (
    v_plant_id, p_occurrence_type_id, v_field_operation_id, now(), p_severity,
    'open', p_notes, p_latitude, p_longitude, p_gps_accuracy_m,
    v_distance_meters, 'nearest_plant', 'confirmed',
    p_local_id, p_device_id, 'synced', now()
  )
  returning id into v_occurrence_id;

  return v_occurrence_id;
end;
$$;

  p_zone_id uuid,
  p_occurrence_type_id uuid,
  p_title text default 'Inspeção'
)

language plpgsql

as $$
declare
  v_operation_type_id uuid;
  v_field_operation_id uuid;

    and po.occurrence_type_id = p_occurrence_type_id
    and po.status = 'open';

-- RPC: get_plant_timeline
-- =========================================================
create or replace function public.get_plant_timeline(p_plant_id uuid)
returns table (
  event_type text,
  event_id uuid,
  title text,
  event_date timestamptz,
  details jsonb
)
language sql
security definer
set search_path = public, extensions
as $$
  select
    'operation' as event_type,
    poh.id as event_id,
    ot.name as title,
    coalesce(poh.matched_at, fo.started_at) as event_date,
    jsonb_build_object(
      'operation_id', fo.id,
      'operation_type', ot.code,
      'distance_meters', poh.distance_meters,
      'match_source', poh.match_source,
      'status', poh.status
    ) as details
  from public.plant_operation_history poh
  join public.field_operations fo on fo.id = poh.field_operation_id
  join public.operation_types ot on ot.id = poh.operation_type_id
  where poh.plant_id = p_plant_id

  union all

  select
    'occurrence' as event_type,
    po.id as event_id,
    oct.name as title,
    po.observed_at as event_date,
    jsonb_build_object(
      'occurrence_code', oct.code,
      'severity', po.severity,
      'status', po.status,
      'notes', po.notes,
      'assignment_method', po.assignment_method,
      'assigned_distance_meters', po.assigned_distance_meters
    ) as details
  from public.plant_occurrences po
  join public.occurrence_types oct on oct.id = po.occurrence_type_id
  where po.plant_id = p_plant_id

  order by event_date desc;
$$;

  title text,
  started_at timestamptz,

)

-- =========================================================
-- RPC: sync_manual_inspection
-- =========================================================
create or replace function public.sync_manual_inspection(p_payload jsonb)
returns table (
  field_operation_id uuid,
  created_occurrences_count integer,
  updated_occurrences_count integer,
  resolved_occurrences_count integer
)
language plpgsql
security definer
set search_path = public, extensions
as $$
declare
  v_operation_type_id uuid;
  v_field_operation_id uuid;
  v_zone_id uuid;
  v_occurrence_type_id uuid;
  v_started_at timestamptz;
  v_finished_at timestamptz;
  v_device_id text;
  v_plant jsonb;
  v_change jsonb;
  v_created_count integer := 0;
  v_updated_count integer := 0;
  v_resolved_count integer := 0;
  v_existing_occurrence_id uuid;
begin
  v_zone_id := nullif(p_payload->>'zoneId', '')::uuid;
  v_occurrence_type_id := nullif(p_payload->>'occurrenceTypeId', '')::uuid;
  v_started_at := nullif(p_payload->>'startedAt', '')::timestamptz;
  v_finished_at := nullif(p_payload->>'finishedAt', '')::timestamptz;
  v_device_id := p_payload->>'deviceId';

  select id into v_operation_type_id
  from public.operation_types
  where code = 'manual_inspection';

  if v_operation_type_id is null then
    raise exception 'operation_types.code manual_inspection não encontrado';
  end if;

  insert into public.field_operations (
    operation_type_id, zone_id, target_occurrence_type_id, source, title,
    started_at, finished_at, device_id, local_id, sync_status, synced_at
  )
  values (
    v_operation_type_id, v_zone_id, v_occurrence_type_id, 'manual', 'Inspeção manual',
    coalesce(v_started_at, now()), v_finished_at, v_device_id,
    p_payload->>'localInspectionId', 'synced', now()
  )
  returning id into v_field_operation_id;

  for v_plant in select * from jsonb_array_elements(coalesce(p_payload->'plantsChanged', '[]'::jsonb))
  loop
    insert into public.plant_operation_history (
      plant_id, field_operation_id, operation_type_id, match_source, status, notes, sync_status, synced_at
    )
    values (
      (v_plant->>'plantId')::uuid, v_field_operation_id, v_operation_type_id,
      'manual_added', 'confirmed', 'Planta alterada durante inspeção manual', 'synced', now()
    )
    on conflict (plant_id, field_operation_id) do nothing;

    for v_change in select * from jsonb_array_elements(coalesce(v_plant->'changes', '[]'::jsonb))
    loop
      v_existing_occurrence_id := null;

      select po.id into v_existing_occurrence_id
      from public.plant_occurrences po
      where po.plant_id = (v_plant->>'plantId')::uuid
        and po.occurrence_type_id = (v_change->>'occurrenceTypeId')::uuid
        and po.status = 'open'
      order by po.observed_at desc
      limit 1;

      if v_change->>'changeType' = 'add_occurrence' then
        if v_existing_occurrence_id is null then
          insert into public.plant_occurrences (
            plant_id, occurrence_type_id, field_operation_id, observed_at, severity,
            status, notes, annotation_latitude, annotation_longitude, gps_accuracy_m,
            assigned_distance_meters, assignment_method, assignment_status,
            local_id, device_id, sync_status, synced_at
          )
          values (
            (v_plant->>'plantId')::uuid,
            (v_change->>'occurrenceTypeId')::uuid,
            v_field_operation_id,
            coalesce(nullif(v_change->>'changedAt', '')::timestamptz, now()),
            nullif(v_change->>'severity', ''),
            'open',
            nullif(v_change->>'notes', ''),
            nullif(v_change->>'latitude', '')::double precision,
            nullif(v_change->>'longitude', '')::double precision,
            nullif(v_change->>'gpsAccuracyM', '')::numeric,
            nullif(v_change->>'distanceToPlantMeters', '')::numeric,
            'manual',
            'confirmed',
            v_change->>'localChangeId',
            v_device_id,
            'synced',
            now()
          );
          v_created_count := v_created_count + 1;
        else
          update public.plant_occurrences
          set
            severity = coalesce(nullif(v_change->>'severity', ''), severity),
            notes = coalesce(nullif(v_change->>'notes', ''), notes),
            field_operation_id = v_field_operation_id,
            updated_at = now(),
            sync_status = 'synced',
            synced_at = now()
          where id = v_existing_occurrence_id;
          v_updated_count := v_updated_count + 1;
        end if;
      elsif v_change->>'changeType' = 'update_occurrence' then
        if v_existing_occurrence_id is not null then
          update public.plant_occurrences
          set
            severity = coalesce(nullif(v_change->>'severity', ''), severity),
            notes = coalesce(nullif(v_change->>'notes', ''), notes),
            field_operation_id = v_field_operation_id,
            updated_at = now(),
            sync_status = 'synced',
            synced_at = now()
          where id = v_existing_occurrence_id;
          v_updated_count := v_updated_count + 1;
        end if;
      elsif v_change->>'changeType' in ('remove_occurrence', 'resolve_occurrence') then
        if v_existing_occurrence_id is not null then
          update public.plant_occurrences
          set
            status = 'resolved',
            resolved_at = coalesce(nullif(v_change->>'changedAt', '')::timestamptz, now()),
            field_operation_id = v_field_operation_id,
            notes = coalesce(nullif(v_change->>'notes', ''), notes),
            updated_at = now(),
            sync_status = 'synced',
            synced_at = now()
          where id = v_existing_occurrence_id;
          v_resolved_count := v_resolved_count + 1;
        end if;
      end if;
    end loop;
  end loop;

  return query select v_field_operation_id, v_created_count, v_updated_count, v_resolved_count;
end;
$$;
```
